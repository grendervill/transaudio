# Transaudio — спецификация первой рабочей версии

**Дата:** 25 октября 2026  
**Выбранное направление:** «Tape Room», макет `mockups/01-tape-room.html`  
**Статус:** спецификация для реализации. Tauri-приложение ещё не начато.

## 1. Задача

Локальное кроссплатформенное приложение для пакетной расшифровки аудио и видео. Пользователь добавляет записи, запускает очередь, читает расшифровку внутри приложения и получает файлы в выбранной папке. Расшифровка выполняется моделью NVIDIA Parakeet TDT 0.6B v3 на устройстве, без отправки медиа в облако.

## 2. Что входит в первую версию

- Три рабочих экрана: «Файлы», «Транскрипция», «Экспорт».
- Добавление нескольких файлов через drag-and-drop и системный выбор файлов.
- Очередь с последовательной обработкой файлов.
- Две шкалы прогресса:
  - текущий файл — под активным файлом в очереди;
  - вся очередь — в нижней панели окна.
- Пауза и продолжение обработки.
- Первый запуск: разрешение на загрузку модели. После выдачи разрешения оно сохраняется и больше не запрашивается.
- Автоматический запуск и загрузка модели при старте приложения, если разрешение уже есть.
- Настройки папки результатов.
- Автоматическое сохранение Markdown-расшифровки каждого готового файла в выбранную папку.
- Экспорт выбранных файлов в Markdown, SRT или TXT.
- Обработка ошибок файла, модели и FFmpeg без падения приложения.
- Работа на macOS, Windows и Linux на уровне исходников и инструкций сборки.

## 3. Вне первой версии

- Диаризация спикеров. Модель не даёт спикеров, приложение не будет их придумывать.
- Ручное редактирование текста и сохранение правок.
- Хранение проектов между запусками и восстановление незавершённой очереди.
- Облачная синхронизация и загрузка медиа на сервер.
- Автоматическое определение языка в интерфейсе (модель делает это сама).
- Перетаскивание файлов внутри очереди и изменение порядка.
- Мобильные платформы.

## 4. Технологические решения

### Каркас

- **Tauri 2** (`@tauri-apps/cli` 2.12.x, Rust 2021).
- **React 19 + TypeScript + Vite** для интерфейса.
- Нативные диалоги — `@tauri-apps/plugin-dialog`.
- Открытие папки — `@tauri-apps/plugin-opener`.
- Копирование текста — `@tauri-apps/plugin-clipboard-manager`.
- Окно: стартовый размер 1440×900, минимум 1024×720, системные decorations.
- Один экран приложения, переключение разделов локальным состоянием; URL-роутер не нужен.

### Модель

- `transcribe-rs = 0.3.12` с feature `onnx`.
- `ort` жёстко зафиксирован на `=2.0.0-rc.12`: версия `rc.15` несовместима с API, которое использует `transcribe-rs 0.3.12`.
- Модель: `parakeet-tdt-0.6b-v3-int8` (NVIDIA Parakeet TDT 0.6B v3, int8 ONNX).
- Источник: `https://blob.handy.computer/parakeet-v3-int8.tar.gz`.
- SHA-256 архива: `43d37191602727524a7d8c6da0eef11c4ba24320f5b4730f1a2497befc2efa77`.
- Размер архива ≈ 456 МБ; после распаковки ≈ 640 МБ.
- В архиве одна папка `parakeet-tdt-0.6b-v3-int8/` с `encoder-model.int8.onnx`, `decoder_joint-model.int8.onnx`, `nemo128.onnx`, `vocab.txt`, `config.json`.
- Модель хранится в `$APP_DATA/models/parakeet-v3-int8`.
- Загрузка: потоковая, с прогрессом, проверкой SHA-256, распаковкой во временную папку и атомарной заменой каталога модели.
- После загрузки модель автоматически загружается в память. При повторном запуске — загружается сразу без вопроса.

### Аудиодвижок

- Источник — FFmpeg CLI.
- Приложение ищет `ffmpeg` в `$APP_DATA/bin`, затем в `PATH`.
- Если FFmpeg не найден, при первом запуске обработки он автоматически скачивается в `$APP_DATA/bin` через `ffmpeg-sidecar` (только бинарник `ffmpeg`, без `ffplay`/`ffprobe`).
- Пользователь видит отдельный статус подготовки аудиодвижка. Ошибка загрузки показывается в интерфейсе.
- Команда конвертации:
  `ffmpeg -nostdin -y -hide_banner -loglevel error -i <input> -vn -ac 1 -ar 16000 -c:a pcm_s16le <temp.wav>`
- Итоговый WAV удаляется после обработки файла.
- Поддерживаемые расширения: `mp3`, `wav`, `m4a`, `flac`, `aac`, `ogg`, `opus`, `mp4`, `mov`, `mkv`, `webm`. Реальная поддержка контейнера/кодека определяется FFmpeg.

### Расшифровка

- Аудио читается в f32-сэмплы 16 кГц, моно.
- Нарезка на окна около 30 секунд; в пределах ±3 секунд выбирается место с минимальной RMS-энергией (естественная пауза).
- Каждое окно транскрибируется `ParakeetModel::transcribe_with` с сегментными таймкодами.
- Таймкоды сегментов смещаются на начало окна.
- После каждого окна UI получает частичные сегменты и обновление прогресса.
- Пауза проверяется между окнами; во время инференса окно не прерывается.
- Текст склеивается с нормализацией пробелов.
- Если речь не распознана, файл получает статус ошибки с понятным сообщением, очередь продолжается.

### Результаты

- Для каждого завершённого файла автоматически пишется Markdown в папку результатов.
- Имя: `<безопасный stem исходника>.md`.
- Markdown содержит заголовок, метаданные и таймкоды/абзацы.
- Экспорт дополнительно умеет SRT и TXT.
- Оригинальные файлы никогда не перемещаются и не изменяются.

## 5. Модель данных

```ts
type Screen = 'files' | 'transcribe' | 'export';

type FileStatus =
  | 'queued'
  | 'processing'
  | 'paused'
  | 'completed'
  | 'error';

type ModelStage =
  | 'consent_required'
  | 'downloading'
  | 'loading'
  | 'ready'
  | 'error';

interface MediaFile {
  id: string;
  path: string;
  name: string;
  extension: string;
  sizeBytes: number;
  status: FileStatus;
  progress: number;          // 0..100
  processedSecs?: number;
  durationSecs?: number;
  segments: TranscriptSegment[];
  text: string;
  savedPath?: string;
  error?: string;
}

interface TranscriptSegment {
  start: number;
  end: number;
  text: string;
}

interface ModelStatus {
  stage: ModelStage;
  progress: number;          // 0..100
  downloadedBytes?: number;
  totalBytes?: number;
  error?: string;
}

interface AppSettings {
  outputDir: string;
  modelConsent: boolean;
  exportFormat: 'md' | 'srt' | 'txt';
}

interface QueueState {
  status: 'idle' | 'running' | 'paused' | 'done';
  overallProgress: number;   // 0..100
  currentId?: string;
  currentIndex: number;      // 0-based
  total: number;
  completed: number;
  failed: number;
}

interface Bootstrap {
  settings: AppSettings;
  model: ModelStatus;
  queue: QueueState;
}
```

## 6. Tauri-команды

| Команда | Вход | Выход | Поведение |
|---|---|---|---|
| `bootstrap` | — | `Bootstrap` | Настройки, статус модели, статус очереди |
| `inspect_files` | `paths: string[]` | `MediaFile[]` + rejected errors | Проверка существования, расширения, размера; создание id |
| `grant_model_consent` | — | `ModelStatus` | Сохраняет разрешение и запускает загрузку |
| `download_model` | — | `ModelStatus` | Повторная загрузка/загрузка после ошибки |
| `set_output_dir` | `path: string` | `AppSettings` | Проверяет/создаёт папку, сохраняет настройки |
| `start_transcription` | `files: {id,path}[]` | `QueueState` | Запускает последовательную очередь |
| `set_paused` | `paused: boolean` | `QueueState` | ставит/снимает паузу |
| `export_results` | `ids: string[], format: 'md'\|'srt'\|'txt'` | `ExportResult` | Пишет файлы в outputDir |
| `open_output_dir` | — | — | Открывает папку в системном файловом менеджере |

События:

| Событие | Payload |
|---|---|
| `model-status` | `ModelStatus` |
| `queue-state` | `QueueState` |
| `file-update` | `{ id, status, progress, processedSecs?, durationSecs?, segments?, text?, savedPath?, error? }` |

## 7. Поведение интерфейса

### Первый запуск

- Если модель отсутствует и `modelConsent = false`, поверх интерфейса открывается модальное окно «Первый запуск».
- В окне: название модели, размер, разрешение на загрузку, пояснение про локальность и FFmpeg.
- «Разрешить и скачать» сохраняет разрешение и показывает прогресс загрузки модели и, при необходимости, FFmpeg.
- «Не сейчас» закрывает окно; экран «Файлы» доступен, но запуск расшифровки заблокирован до готовности модели. При следующем запуске вопрос появится снова.
- После готовности модели модальное окно закрывается автоматически.
- Если модель уже есть, она загружается без модального окна.

### Файлы

- Пустое состояние: dropzone и подсказка.
- Drag-and-drop из ОС: добавление всех путей.
- Кнопка «Добавить файлы»: системный диалог, множественный выбор.
- Некорректные файлы не добавляются; показывается уведомление.
- В очереди: номер, имя, формат/размер, статус, удаление (только в покое).
- Папка результатов, статус модели, суммарный размер.
- «Начать» доступна при наличии файлов и готовой модели. Запускает очередь и переключает на «Транскрипцию».
- После завершения кнопка становится «Транскрибация завершена»; новый запуск возможен после очистки списка.

### Транскрипция

- Слева — очередь файлов и отдельная шкала текущего файла под активным элементом.
- Справа — активная расшифровка. Завершённые файлы свёрнуты в строки, которые раскрываются.
- Пока идёт файл, его сегменты дописываются по мере готовности.
- Внизу — общая шкала, текущий файл, «осталось примерно», пауза.
- Копирование текста и открытие папки.

### Экспорт

- Список готовых файлов с чекбоксами.
- Пустая папка/нет результатов — пустое состояние.
- Формат: Markdown / SRT / TXT.
- Путь сохранения, кнопка «Экспортировать N файлов».
- Пояснение, что Markdown-копии уже сохраняются автоматически.

### Настройки

- Папка результатов с нативным выбором.
- Модель: статус, размер, «запускается вместе с приложением» (нельзя выключить — это требование).
- Разрешение на загрузку: «получено, повторно не спрашиваем».
- Кнопка повтора загрузки при ошибке.
- Открыть папку.

## 8. Кроссплатформенность

- Пути и папки — только через `PathBuf` и Tauri path API; без строковых `/` и `~`.
- На macOS папка документов и поддержка приложения — стандартные Tauri пути.
- На Windows иконки, диалоги и папки — через Tauri; сборка MSI/NSIS.
- На Linux — WebKitGTK 4.1; зависимости сборки описаны в README.
- FFmpeg для отсутствующей платформы скачивается через `ffmpeg-sidecar`.
- ONNX Runtime поставляется статически через `ort` default-сборку; проверить, что release-бандл запускается без отдельного dylib.
- CI-матрица сборки macOS/Windows/Ubuntu добавляется в репозиторий, даже если локально проверяется только macOS.

## 9. Критерии готовности

1. Приложение запускается через `npm run tauri dev`.
2. Первый запуск показывает разрешение, после загрузки модели работает без повторного вопроса.
3. Можно добавить 2+ файла drag-and-drop и через диалог.
4. Очередь обрабатывает файлы последовательно.
5. Текущий файл и общий прогресс обновляются в двух разных местах.
6. Пауза останавливает переход к следующему окну и возобновляется.
7. Расшифровка русского аудио отображается в приложении с таймкодами.
8. Markdown автоматически появляется в выбранной папке.
9. Экспорт SRT/TXT/MD создаёт корректные файлы.
10. Ошибка отдельного файла не ломает очередь.
11. В приложении нет вымышленных спикеров и фальшивых данных.
12. Интерфейс визуально проверен на macOS в окне 1440×900 и 1024×768.
13. `npm test`, `npm run build`, `cargo test` проходят.
14. README описывает запуск на macOS, Windows и Linux и путь получения модели и FFmpeg.

## 10. Проверка

- Rust: `cargo test` для настроек, чанков, писателей файлов, разбора путей и статусов.
- React: Vitest + Testing Library для экранов, блокировок, статусов, модальных окон.
- Сборка: `npm run build` + `cargo check`.
- Ручной E2E на macOS: реальная модель, русская тестовая запись, MP4 и MP3, отмена паузы, экспорт, перезапуск приложения.
- Визуальная проверка окна через macOS tools; скриншот приложить в отчёт.
