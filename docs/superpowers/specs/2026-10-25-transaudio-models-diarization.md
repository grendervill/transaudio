# Transaudio 0.2 — модели Handy, диаризация и очередь

**Дата:** 25 октября 2026
**Статус:** дизайн утверждён, движок заменён на transcribe-cpp
**База:** Transaudio 0.1.1

## 1. Зачем

Parakeet V3 — единственная модель, очередь после завершения не даёт добавить
файл, готовые записи расшифровываются повторно, спикеры не разделяются.
Нужно: не повторять готовое, открывать расшифровку кликом, выбрать модель из
каталога Handy с понятными шкалами и рекомендациями, разделять спикеров.

## 2. Движок

Приложение переходит с `transcribe-rs` + ONNX Runtime на
**`transcribe-cpp 0.4.1`** — тот же C++/GGML-движок, который использует Handy.

- Модели — одиночные GGUF-файлы с Hugging Face (`handy-computer/*`), SHA-256
  берётся из каталога Handy.
- На macOS автоматически включается Metal, на Windows/Linux — CPU.
- Результат содержит текст, сегменты в миллисекундах, слова, определённый язык.
- `transcribe-rs`, `ort`, `hound` (кроме чтения WAV в чанкере) удаляются.
- Проверено: сборка 28 с, GigaAM v3 Q8_0 — корректный русский текст с
  пунктуацией, 0,32 с на 6,9 с аудио.

Диаризация остаётся на `sherpa-onnx 2.0.0` (проверена: 2 спикера, 5 реплик,
1,5 с на 26,5 с).

- Шкала скорости: `≥25 → 5`, `12–25 → 4`, `6–12 → 3`, `3–6 → 2`, `<3 → 1`.
- Шкала качества: `WER ≤4.5 → 5`, `≤5.5 → 4`, `≤6.5 → 3`, `≤8 → 2`, `>8 → 1`;
  для карточки берётся лучший WER среди поддерживаемых RU/EN, иначе лучший
  доступный язык. Рядом выводятся сами WER: «EN 4,8% · RU 6,5%».
- «Рекомендую · английский» — Parakeet Unified English (лучший EN WER при
  14× realtime). «Рекомендую · русский» — GigaAM v3 RNNT (5,35% RU, 261 МБ,
  7,9×); Whisper large-v3 точнее по RU (4,96%), но 1,6 ГБ и 1× — у него плашка
  «максимум точности».
- Canary не умеет автоопределять язык: в карточке селектор языка записи,
  по умолчанию русский. Остальные модели определяют язык сами.
- Для каждой карточки: имя, описание, языки (список или «99 языков»), размер,
  шкалы, WER, лицензия, состояние (выбрана / скачать / загрузка / удалить).

Ссылки на скачивание строятся как
`https://huggingface.co/{repository}/resolve/{revision}/{filename}`; repository,
revision, имя файла, размер и SHA-256 зашиты в каталог из `catalog.json` Handy.
Установка: временный файл → проверка SHA-256 → атомарное переименование в
`models/<id>/<filename>`. Установленные модели можно удалять, кроме выбранной.

### Миграция

- Старый каталог `models/parakeet-v3-int8` (ONNX) больше не используется.
  Он удаляется после успешной установки GGUF-версии Parakeet.
- Parakeet скачивается один раз заново (705 МБ). Это указано в заметках к
  релизу и в интерфейсе при первом запуске 0.2.
- `settings.json` без новых полей читается с значениями по умолчанию.

## 4. Очередь и готовые файлы

- «Начать» активна, если есть хотя бы один файл со статусом `queued` или
  `error`, модель готова, очередь не выполняется.
- Добавление файла после завершения очереди не блокирует кнопку.
- На обработку уходят только нерасшифрованные файлы; готовые не отправляются
  и не теряют текст. Результаты хранятся по id и не очищаются при новом запуске.
- Клик по любому файлу в очереди открывает его расшифровку в «Транскрипции».
  Для нерасшифрованного — «Файл ещё не расшифрован», для ошибки — причина.
- «Очистить» сбрасывает список, но не удаляет сохранённые Markdown-копии.
- Чтобы сравнить модели на одном файле: удалить файл из списка и добавить
  снова (новый id → новая расшифровка). Отдельной кнопки «заново» нет.

## 5. Диаризация

- Модели: pyannote segmentation 3.0 (`model.onnx`, 5,7 МБ) + CAM++ embedding
  (27 МБ). Скачиваются при первом включении, SHA-256 зашит.
- Сценарии и порог: «Интервью / диалог (2–3)» — 0.45 (по умолчанию),
  «Встреча (4–6)» — 0.35, «Много участников (7+)» — 0.30, «Авто» — 0.40.
- Пайплайн: полный WAV → диаризация → склейка соседних реплик одного спикера
  (разрыв ≤0.4 с), поглощение реплик короче 0.5 с, отступ 0.15 с → каждая
  реплика до 30 с транскрибируется выбранной моделью → сегменты получают
  спикера и точное время.
- Поэтому подписи работают и с моделями без таймкодов (Canary, SenseVoice).
- Файлы длиннее 2 часов: диаризация отключается с сообщением, обычная
  расшифровка продолжается.
- Спикеры нумеруются по первому появлению: «Спикер 1», «Спикер 2».
- UI: цветные плашки спикеров, группировка соседних реплик.
- Экспорт: MD `**Спикер 1** · [00:00:03] текст`; SRT `Спикер 1: текст`;
  TXT `Спикер 1: текст`.
- По умолчанию выключена; переключатель и сценарий — на экране файлов.

## 6. Интерфейс

- **Файлы:** выбранная модель и «Сменить», переключатель «Спикеры» и сценарий,
  прогресс загрузки моделей спикеров.
- **Настройки:** карточки моделей (сетка 2 колонки, прокрутка), фильтры
  «Все / Русский / Английский / Азиатские».
- **Первый запуск:** те же карточки, Parakeet выбран по умолчанию, кнопка
  показывает размер выбранной модели.
- **Транскрипция:** очередь слева, клик по файлу показывает его текст справа;
  у текущего файла — прогресс, у готовых — «Готово».

## 7. Данные и команды

```json
{
  "output_dir": "...",
  "model_consent": true,
  "export_format": "md",
  "model_id": "parakeet-tdt-0.6b-v3",
  "canary_language": "ru",
  "diarization": false,
  "diarization_scenario": "interview"
}
```

Команды: `list_models`, `select_model(id)`, `download_model(id)`,
`delete_model(id)`, `set_canary_language(lang)`,
`set_diarization(enabled, scenario)`, плюс существующие `bootstrap`,
`inspect_files`, `start_transcription`, `set_paused`, экспорт.

События: `model-status` (id + stage + progress), `diarization-status`,
`queue-state`, `file-update`.

## 8. Вне версии

- Переименование спикеров, голосовые профили между файлами.
- Автоопределение языка для Canary.
- Модели с GPU-требованиями (Voxtral 24B, Granite 2B) и медицинские/арабские
  узкоспециальные варианты.
- Редактирование текста, восстановление очереди после перезапуска, облако.

## 9. Риски

- Сборка `transcribe-cpp-sys` (C++/CMake) на пяти целях CI. Handy собирает его
  для Windows ARM64 и Apple Silicon; проверяем в CI.
- Приложение вырастет: transcribe-cpp + sherpa-onnx статически.
- Whisper large-v3 на CPU медленный (1× realtime) — честно на шкале.
- Диаризация на похожих голосах ошибается; сценарий и порог помогают.
- Модели Handy имеют разные лицензии (CC-BY-4.0, MIT, Apache-2.0, «other» для
  SenseVoice) — атрибуция в README и карточке.

## 10. Проверка

- Rust: парсинг каталога, установка GGUF с SHA-256, миграция настроек,
  склейка/обрезка реплик, назначение спикера, пороги сценариев, удаление модели.
- React: карточки, шкалы, плашки, фильтры, выбор модели, блокировка «Начать»,
  отправка только неготовых, клик по готовому файлу, плашки спикеров.
- E2E на macOS: Parakeet v3 (GGUF), GigaAM v3, Whisper turbo, двухголосый файл,
  A готов → добавить B → расшифровать только B → открыть A → экспорт A и B.
- CI на пяти целях, релиз 0.2.0.
